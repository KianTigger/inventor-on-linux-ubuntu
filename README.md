# Autodesk Inventor 2026 on Ubuntu 22.04 via Wine

This repository is an **Ubuntu 22.04 (Jammy) port** of the Inventor-on-Linux workflow originally demonstrated on Arch/CachyOS. It targets **Autodesk Inventor 2026 Professional + vanilla Wine 11.4 + DXVK 2.7.1**.

> **Important:** the scripts in this port have been made Ubuntu-aware and statically validated, but an end-to-end Inventor launch cannot be validated without your Windows Inventor installation, Autodesk account/license, and target GPU/display session. The binary compatibility patches remain tied to the tested Inventor/Wine versions.

## What this repository does

The scripts build a Wine prefix by copying a **working Windows Inventor 2026 installation** and the Autodesk components it depends on. This is not a replacement Inventor installer and does not bypass Autodesk licensing. First-time activation still requires a valid Autodesk subscription and browser-based SSO.

The Ubuntu port additionally:

- installs Ubuntu 22.04 dependencies with `apt` instead of `pacman`;
- installs and pins **WineHQ development 11.4** rather than Ubuntu's older/default Wine;
- installs upstream **DXVK 2.7.1** directly instead of Arch's `dxvk-mingw-git` / `setup_dxvk` helper;
- downloads the Microsoft WebView2 Evergreen x64 installer;
- detects the correct WineHQ `wbemprox.dll` installation path before applying the Wine patch;
- supports configurable Windows mount paths, data-drive mappings, GPU UUID selection, and server display variables;
- can auto-detect a same-user GNOME graphical session when launched from a plain SSH shell;
- imports the Autodesk registry export generated by `export-registry.sh`;
- performs preflight checks before deleting/rebuilding a Wine prefix;
- refuses to apply the fixed-offset `OGSFactory.dll` patch to an unrecognised binary.

## Tested target

### Linux host

- **Ubuntu 22.04.x LTS (Jammy)**
- **x86_64**
- **Linux kernel 6.x or newer**
- a Vulkan-capable GPU and working proprietary/open Vulkan driver
- a graphical X11/Wayland session for Inventor itself

A server without a monitor can still be usable, but Inventor is a GUI Windows application. It must have a graphical session (for example a local GNOME session, remote desktop session, or other usable X/Wayland session). A plain SSH shell with no graphical session is not sufficient by itself.

### Pinned compatibility stack

| Component | Required/tested version |
|---|---:|
| Wine | **11.4** vanilla WineHQ devel |
| DXVK | **2.7.1** |
| Inventor | **2026 Professional** |
| Autodesk Licensing | **15.4.2.4** by default |
| Windows compatibility mode | Windows 10 |

Do not casually upgrade Wine or DXVK while debugging. The included `wbemprox` patch is built against Wine 11.4 and the OGS binary patch is tied to the tested Inventor binary layout.

### Windows source requirement

You need access to a Windows installation where Inventor 2026 is already installed and working. By default the scripts expect that Windows filesystem at:

```text
/mnt/windows
```

This can be a mounted Windows partition, a read-only copy of a Windows filesystem, or another filesystem exposed to Ubuntu with the same directory structure. Configure a different location in `inventor.env` if needed.

**No existing Windows partition on the Linux server?** This port now includes a complete Windows 11 staging-VM workflow using KVM/QEMU + libvirt. Install Inventor normally in the VM, shut Windows down, then mount the VM's C: drive read-only at `/mnt/windows` with `libguestfs`. See **[docs/windows-vm.md](docs/windows-vm.md)**.

The VM path is designed for a Linux-only server: its VNC console binds only to server localhost and is reached through an SSH tunnel. It does not require exposing a VNC port publicly.

Required source locations include:

```text
Windows/System32
Program Files/Autodesk/Inventor 2026
Program Files/Autodesk/AdskIdentityManager/Current
Program Files/Common Files/Autodesk Shared
Program Files (x86)/Common Files/Autodesk Shared/AdskLicensing/15.4.2.4
ProgramData/Autodesk
Users/<windows-user>/NTUSER.DAT
```

## Quick start

Run everything as the **normal Linux account that will run Inventor**. Do not run the repository scripts as root unless a command explicitly invokes `sudo` internally.

```bash
# 1. Configure the repository
cp inventor.env.example inventor.env
nano inventor.env

# 2. Install Ubuntu dependencies, WineHQ 11.4, DXVK 2.7.1 and WebView2
bash scripts/phase0-setup.sh

# 3. Prepare a Windows source. If this server has no Windows partition, use:
#    docs/windows-vm.md
# The VM workflow ends with its offline C: drive mounted at /mnt/windows.

# 4. Check the host, Vulkan, display and mounted Windows source
bash scripts/doctor.sh

# 5. Export Autodesk registry data from the mounted Windows installation
bash scripts/export-registry.sh

# 6. Build a fresh Wine prefix from the Windows source
bash scripts/rebuild-prefix.sh

# 7. Build/install the Wine 11.4 Win32_TimeZone patch
bash scripts/install-wbemprox-patch.sh

# 8. Register Autodesk OAuth callback and desktop integration
bash scripts/setup-user-integration.sh

# 9. Re-run checks, then launch
bash scripts/doctor.sh
bash scripts/launch-inventor.sh
```

The rebuild is intentionally destructive to `WINEPREFIX`. If a prefix already exists, the script requires you to type `REBUILD`. For unattended/reprovisioning use:

```bash
bash scripts/rebuild-prefix.sh --force
```

## 1. Configure `inventor.env`

`inventor.env` is local configuration and is gitignored. Start from the included example:

```bash
cp inventor.env.example inventor.env
```

Common settings:

```bash
WINDOWS_MOUNT="/mnt/windows"
WINDOWS_USER=""
WINEPREFIX="$HOME/.wine-inventor2026"
DATA_DRIVE=""
DXVK_FILTER_DEVICE_UUID=""
```

`WINDOWS_USER` can normally remain empty; the scripts auto-detect the first non-system Windows profile. Set it explicitly if the Windows installation contains multiple real user profiles.

### Optional D: data drive

To map a Linux directory as Wine drive `D:`:

```bash
DATA_DRIVE="/mnt/Storage"
```

The rebuild creates the `D:` symlink only when this directory exists.

## 2. Ubuntu host setup (`phase0-setup.sh`)

Run:

```bash
bash scripts/phase0-setup.sh
```

The script verifies Ubuntu 22.04/x86_64/kernel 6+, enables the `i386` architecture and Ubuntu `universe` repository, and installs the required Ubuntu packages including:

- `libhivex-bin`
- `winetricks`
- `imagemagick`
- `rsync`
- `cabextract`
- `p7zip-full`
- `desktop-file-utils`
- `xdg-utils`
- `vulkan-tools`
- `pciutils`
- `libvulkan1` and `libvulkan1:i386`
- Wine build dependencies used by the `wbemprox` patch

It then configures the official WineHQ Jammy repository and searches that repository for **exactly Wine 11.4**. It will stop instead of silently installing a newer release if 11.4 is unavailable.

WineHQ's `winehq-devel` package installs the development branch under `/opt/wine-devel`. All repository scripts prefer that path so another system Wine installation does not accidentally get used.

The script also holds the Wine 11.4 packages with `apt-mark` because a Wine upgrade would overwrite the compatibility DLL and change the runtime being tested.

To intentionally remove the hold later:

```bash
sudo apt-mark unhold winehq-devel wine-devel wine-devel-amd64 'wine-devel-i386:i386'
```

Do this only when you plan to port/retest the Wine patch against the new Wine version.

### NVIDIA and 32-bit userspace libraries

For NVIDIA systems the setup script checks the installed driver major version and, if the matching Ubuntu package exists, installs the corresponding `libnvidia-gl-<major>:i386` package. This helps 32-bit Wine components use the same proprietary driver stack.

If your NVIDIA driver was installed outside APT and no matching i386 package is available, the script prints a warning instead of changing the driver installation.

## 4. Multi-GPU servers

List Vulkan GPU names/UUIDs and NVIDIA utilisation:

```bash
bash scripts/list-gpus.sh
```

For machines containing multiple identical GPUs, use the UUID rather than the device name. DXVK 2.7.1 accepts a 32-character Vulkan UUID with no dashes:

```bash
DXVK_FILTER_DEVICE_UUID="0123456789abcdef0123456789abcdef"
```

Add that to `inventor.env`. The launcher normalises UUIDs with dashes but validates that the final value is exactly 32 hexadecimal characters.

If the setting is omitted, DXVK chooses a Vulkan device automatically. On compute servers this may select a GPU already occupied by another workload, so explicit pinning is recommended.

## 5. Ubuntu server / SSH display setup

`vulkaninfo --summary` can enumerate GPUs without `DISPLAY`, but Inventor cannot create its GUI without a graphical session.

The launcher resolves the display in this order:

1. explicit values from `inventor.env`;
2. `DISPLAY`/`XAUTHORITY` already present in the shell;
3. environment variables read from a `gnome-shell` process owned by the **same Linux user**.

This means a plain SSH login can often launch Inventor into an already-running GNOME session owned by that same account.

Check what the repository sees:

```bash
bash scripts/doctor.sh
```

If automatic detection does not work, inspect your graphical session from the same user account:

```bash
pgrep -u "$(id -u)" -x gnome-shell
tr '\0' '\n' < /proc/$(pgrep -u "$(id -u)" -x gnome-shell | head -1)/environ \
  | grep -E '^(DISPLAY|XAUTHORITY|DBUS_SESSION_BUS_ADDRESS|XDG_RUNTIME_DIR)='
```

Then set the values in `inventor.env`, for example:

```bash
INVENTOR_DISPLAY=":0"
INVENTOR_XAUTHORITY="/run/user/1000/gdm/Xauthority"
INVENTOR_XDG_RUNTIME_DIR="/run/user/1000"
INVENTOR_DBUS_SESSION_BUS_ADDRESS="unix:path=/run/user/1000/bus"
```

Use the paths reported by your machine; the values above are examples only.

Avoid broad access workarounds such as `xhost +`. If the desktop session belongs to another Linux account, configure a proper remote desktop/service account design rather than bypassing X authentication globally.

### First Autodesk SSO login

First launch requires a default web browser in a usable desktop session. `scripts/doctor.sh` warns when no default desktop browser is detected. Autodesk redirects to the `adskidmgr://` URI scheme. `setup-user-integration.sh` registers that scheme with the Linux desktop and points it at `scripts/adskidmgr-callback.sh`.

After a successful login the Autodesk token/cache may allow subsequent launches without repeating the browser flow.

## 6. Prepare/mount the Windows source

The simplest layout is:

```text
/mnt/windows/Windows
/mnt/windows/Program Files
/mnt/windows/Program Files (x86)
/mnt/windows/ProgramData
/mnt/windows/Users
```

A physical NTFS partition can be mounted read-only if desired; the scripts only read the Windows source.

### Recommended for a Linux-only server: Windows staging VM

This repository includes Ubuntu 22.04 KVM/libvirt helpers:

```bash
cp windows-vm.env.example windows-vm.env
nano windows-vm.env

bash scripts/vm/setup-windows-vm-host.sh
# Log out/in after the group-membership change.

bash scripts/vm/create-windows-vm.sh
```

Install Windows 11 + Inventor 2026 in the VM, disable hibernation and BitLocker/device encryption, then shut the VM down completely.

On Ubuntu 22.04, the packaged libguestfs stack may fail in two different ways when mounting a current Windows 11 QCOW2 image:

1. the default/libvirt backend can report `Permission denied` while opening `/var/lib/libvirt/images/inventor-win11.qcow2`;
2. after switching to the direct backend, automatic `guestmount -i` inspection can report `no operating system was found on this disk` even though Windows is installed correctly.

The reliable fallback is to use libguestfs' **direct backend** and mount the Windows partition explicitly. First identify the partitions:

```bash
sudo env LIBGUESTFS_BACKEND=direct \
  virt-filesystems \
    -a /var/lib/libvirt/images/inventor-win11.qcow2 \
    --all --long -h
```

For the documented VM created on Ubuntu 22.04, the Windows C: partition was `/dev/sda3`. Confirm it before mounting; do not assume the same partition number if you changed the VM layout.

Prepare the FUSE mount once:

```bash
grep -qE '^[[:space:]]*user_allow_other' /etc/fuse.conf \
  || echo 'user_allow_other' | sudo tee -a /etc/fuse.conf

sudo mkdir -p /mnt/windows
sudo chown "$USER":"$USER" /mnt/windows
```

Then mount the powered-off VM read-only:

```bash
sudo env LIBGUESTFS_BACKEND=direct \
  guestmount \
    -a /var/lib/libvirt/images/inventor-win11.qcow2 \
    -m /dev/sda3 \
    --ro \
    -o allow_other \
    -o uid="$(id -u)" \
    -o gid="$(id -g)" \
    /mnt/windows
```

Verify:

```bash
findmnt /mnt/windows
ls -la /mnt/windows
ls "/mnt/windows/Program Files/Autodesk/Inventor 2026"
```

The top-level tree should contain `Windows`, `Program Files`, `Program Files (x86)`, `ProgramData`, and `Users`. `findmnt` may display the outer FUSE transport as `rw`; the Windows filesystem inside libguestfs is still mounted read-only because `guestmount` was invoked with `--ro`.

**Do not start the VM while `/mnt/windows` is mounted.** The detailed manual partition-discovery and troubleshooting sequence is in **[docs/windows-vm.md](docs/windows-vm.md)**.

The complete installation/console/Windows-preparation/lifecycle instructions are in **[docs/windows-vm.md](docs/windows-vm.md)**. The documented default assumes an **Ubuntu/Linux workstation** and TigerVNC Viewer. Windows Setup is graphical, so a graphical VM console is required.

On the Ubuntu/Linux workstation where you will view the VM:

```bash
sudo apt update
sudo apt install -y tigervnc-viewer
```

Create the SSH tunnel from that workstation:

```bash
ssh -N -L 5905:127.0.0.1:5905 ai4@SERVER_IP
```

For the current `AI-Server` address:

```bash
ssh -N -L 5905:127.0.0.1:5905 ai4@192.168.101.172
```

Leave that SSH command running, then open another workstation terminal:

```bash
vncviewer 127.0.0.1::5905
```

The double colon tells TigerVNC that `5905` is the literal TCP port. On first boot, if the VNC window shows the grey OVMF/UEFI screen with `Select Language`, `Device Manager`, and `Boot Manager`, that is **firmware, not Windows Setup**. Choose **Boot Manager**, then select the QEMU DVD/CD-ROM containing the Windows ISO and press a key when prompted to boot from it.

During Windows installation the VM reboots several times. TigerVNC may close with an `End of stream` message while QEMU/firmware resets the display. **That does not mean the Windows installation failed.** Keep or recreate the SSH tunnel, confirm the VM is running with `virsh domstate inventor-win11`, and reconnect with:

```bash
vncviewer 127.0.0.1::5905
```

After Windows has copied files to the virtual disk, do **not** press a key at later `Press any key to boot from CD or DVD...` prompts. Let the VM boot from the virtual disk. If OVMF appears again, use **Boot Manager -> Windows Boot Manager** rather than the DVD/CD-ROM entry.

For Windows account setup, install **Windows 11 Pro**. If you want to avoid a personal Microsoft account during OOBE, choose **Set up for work or school**, then **Sign-in options -> Domain join instead** when those options are offered. This opens local-user creation; the VM does not actually need to join a domain. A local account such as `inventor` is appropriate for this staging VM. Autodesk sign-in is separate and is still required later for Autodesk licensing/SSO. See the detailed VM guide for the full sequence and current-version caveats.

The alternative is to use `virt-viewer` directly from `AI-Server`'s local GNOME desktop; see the detailed VM guide.

Before rebuilding, verify:

```bash
bash scripts/doctor.sh
```

The doctor checks the expected Inventor, Identity Manager and Licensing Service source directories.

## 8. Rebuild the Wine prefix

Run:

```bash
bash scripts/rebuild-prefix.sh
```

The rebuild performs a source-tree preflight **before** deleting an existing Wine prefix. Major operations include:

1. create a clean Wine 11.4 win64 prefix;
2. set Windows 10 compatibility;
3. install DXVK 2.7.1 using upstream DLLs;
4. copy Inventor, Shared Components, MSVC/MFC runtimes and RealDWG;
5. start the WebView2 Evergreen installer;
6. copy Autodesk Identity Manager and Licensing Service;
7. copy available Autodesk license/cache files;
8. import `registry/autodesk-full.reg`;
9. apply required Inventor/SharedComponents/licensing/protocol registry keys;
10. install the IDSDK SSO plugin into the licensing agent;
11. disable known Wine-broken/non-essential add-ins;
12. copy .NET 8, Design Data, Templates and Textures when present;
13. apply the tested `OGSFactory.dll` null-pointer patch;
14. create the optional `D:` mapping.

### OGS binary safety check

The OGS patch writes machine code at fixed file offsets. The Ubuntu port first checks the bytes at the tested crash site. If your `OGSFactory.dll` comes from a different Inventor build, the script stops rather than corrupting the DLL.

If this happens, do not bypass the check. The patch must be re-derived for that Inventor build.

## 9. Wine `wbemprox` / `Win32_TimeZone` patch

Run after Wine 11.4 is installed:

```bash
bash scripts/install-wbemprox-patch.sh
```

This script:

1. downloads the matching Wine 11.4 source;
2. applies `patches/wbemprox-timezone.patch`;
3. configures a minimal Wine build tree;
4. builds only `dlls/wbemprox`;
5. discovers the active WineHQ installation root from the configured Wine binary;
6. finds the actual `x86_64-windows/wbemprox.dll` beneath that installation;
7. preserves the packaged DLL as `wbemprox.dll.inventor-original`;
8. installs the patched DLL with `sudo`.

This replaces the original Arch-specific assumption that the DLL lives at `/usr/lib/wine/x86_64-windows/wbemprox.dll`. WineHQ devel packages normally live under `/opt/wine-devel`, but the script detects the actual location rather than hard-coding it.

A Wine package upgrade will overwrite this change. Phase 0 therefore pins Wine 11.4.

## Troubleshooting

### `pacman: command not found`

You are using the original Arch instructions or an old copy of `phase0-setup.sh`. The Ubuntu port does not use `pacman`.

```bash
bash scripts/phase0-setup.sh
```

### `Wine 11.4 not detected`

Check both the system command and the WineHQ devel path:

```bash
wine --version 2>/dev/null || true
/opt/wine-devel/bin/wine --version
```

Repository scripts prefer `/opt/wine-devel/bin/wine` when present.

### WineHQ no longer exposes Wine 11.4 in APT

`phase0-setup.sh` intentionally stops. Confirm available versions:

```bash
apt-cache madison winehq-devel
```

Do not substitute a newer Wine version without retesting/rebuilding the compatibility patch.

### `DISPLAY` is unset over SSH

This is normal for a plain SSH session. Run:

```bash
bash scripts/doctor.sh
```

If the same user owns a running GNOME session, the launcher attempts to reuse its environment. Otherwise configure the explicit display variables in `inventor.env`.

### `vulkaninfo` says DISPLAY is not set

Surface-information warnings are expected from an SSH shell. The important test is whether discrete GPU devices are enumerated successfully. Inventor itself still needs a graphical session at launch time.

### DXVK chooses the wrong GPU

```bash
bash scripts/list-gpus.sh
```

Copy the desired device's UUID into `DXVK_FILTER_DEVICE_UUID` in `inventor.env`.

### WebView2 installation problems

The downloaded installer is stored at:

```text
~/.cache/inventor-on-linux/MicrosoftEdgeWebView2RuntimeInstallerX64.exe
```

The rebuild writes its Wine installer output to a WebView2 installation log. Re-run phase 0 to redownload the installer if the file is absent/corrupt.

### OGS patch refuses to run

Your `OGSFactory.dll` does not match the tested binary. This is a deliberate safety failure. Restore/use the exact compatible Inventor 2026 build or re-derive the offsets for your binary.

### Autodesk Licensing version differs

The tested/default version is:

```bash
ADSK_LICENSING_VERSION="15.4.2.4"
```

If the Windows installation has another version, changing the variable may be necessary, but the SSO/licensing compatibility workflow should then be treated as untested.

### Full host report

```bash
bash scripts/doctor.sh
```

Fix all `FAIL` entries before rebuilding. Warnings can be contextual (for example no registry export before you have run `export-registry.sh`).

## Technical Details

### OGSFactory.dll Binary Patch

#### Root Cause

OGSFactory.dll queries WMI during 3D viewport creation. The function at RVA `0x57968`:

1. Calls `IWbemServices::CreateInstanceEnum()` (vtable slot 18) for `Win32_TimeZone`
2. Calls `IEnumWbemClassObject::Next(2000, 1, &ppObject, &uReturned)` (vtable slot 4)
3. Uses the returned object to set up the Protein material/lighting pipeline

Under Wine, `Next()` returns `S_OK` but leaves `ppObject = NULL`. The function then unconditionally dereferences `[ppObject]`, causing access violation 0xC0000005.

The crash occurs inside a Win32 window message callback. Wine's `user_callback_handler` logs `"ignoring exception c0000005"` and continues with corrupted state. On Windows, `legacyCorruptedStateExceptionsPolicy` would catch this. Under Wine it is fatal.

#### The Fix

Two code-cave patches redirect the crash sites to null-check trampolines written into `.text` section padding:

**Patch 1** — file offset `0x56E5B` (RVA `0x57A5B`):

```asm
; Original (crashes when rcx = NULL):
;   mov  rcx, [rsp+0x70]
;   mov  rdx, [rcx]         ← access violation
;
; Replaced with: jmp to code cave at 0x110A60
e9 00 9c 0b 00   ; jmp  +0xB9C00
90 90 90         ; nop  nop nop  (alignment padding)

; Code cave at file offset 0x110A60:
48 8b 4c 24 70   ; mov  rcx, [rsp+0x70]
48 85 c9         ; test rcx, rcx
0f 84 11 64 f4 ff; je   0x57A7F          ; skip to cleanup if NULL
48 8b 11         ; mov  rdx, [rcx]       ; safe dereference
e9 ed 63 f4 ff   ; jmp  0x57A63         ; return to normal flow
```

**Patch 2** — file offset `0x56EA8` (RVA `0x57AA8`): same pattern, second dereference of the same pointer. Code cave at `0x110A76`.

### Key Discoveries

Non-obvious facts found during the porting work. Read these before investigating any open issue.

**1. WPF GAC removal is mandatory.**
Wine-mono ships stub WPF DLLs in the GAC (`PresentationCore`, `PresentationFramework`, `WindowsBase`, `System.Xaml`). When Inventor loads, mono hits a fatal assertion in the stub and calls `System.Environment.Exit()`. Deleting only the DLL files (not the directories) is the fix. `wineboot -u` recreates directories but not files, so the fix persists.

**2. bcp47langs.dll Proton stub causes a NULL crash.**
Proton ships a stub `bcp47langs.dll` that returns NULL from all calls. This crashes all Autodesk apps. Remove the file or disable the DLL override entirely.

**3. Identity Manager uses Boost.Interprocess for IPC.**
The IDSDK IPC directory (`$WINEPREFIX/drive_c/ProgramData/Autodesk/IDSDK/<USERNAME_HEX>/interprocess/01000000/`) must be wiped before each launch. Stale lock files cause Identity Manager to deadlock indefinitely. The directory name is the ASCII username encoded as uppercase hex (e.g. `alice` → `616C696365`); the launch script computes this dynamically.

**4. OAuth2 callback: launch a client, never kill wineserver.**
The `adskidmgr://` handler must spawn a new Identity Manager *client* instance (which passes the auth code and exits). Killing `wineserver` destroys the running Inventor session.

**5. CER crash reporter terminates the process.**
Autodesk's `senddmp.exe` intercepts native crashes, shows a report dialog, then exits the process. Disabling it by renaming allows Inventor to survive recoverable crashes.

**6. .NET 8 CoreCLR runs under Wine 11.4.**
Load chain: `ClrAddinLoader.dll` → `hostfxr.dll` → `hostpolicy.dll` → `coreclr.dll`. Use `WINEDLLOVERRIDES="msquic="` to suppress MSQUIC networking crashes.

**7. Wine's user_callback_handler swallows exceptions.**
A native crash inside a Win32 window message callback logs `"ignoring exception c0000005"` and continues. On Windows the exception propagates to the managed handler. Under Wine it is silently absorbed, leaving corrupted state that eventually terminates the process.

**8. DXVK always reports AMD Radeon RX 6700 XT.**
Regardless of actual GPU hardware. May affect OGS GPU capability detection but has no functional impact on D3D11 rendering.

**9. IDSDK SSO plugin must be manually placed in the Licensing Agent.**
The `IDSDKVersionCompatibility.config` file and `SSOPlugin/Current/*.dll` must exist under the Licensing Agent directory. They are not discovered from the Identity Manager installation path.

**10. OGS queries three WMI classes during graphics init.**
`Win32_TimeZone`, `Win32_VideoController`, and `Win32_BIOS` are queried from `OGSFactory.dll!fn@0x57968`. Missing classes cause silent pipeline degradation or a crash.

Stored in `user.cfg` inside the Wine prefix. **Do not change these unless you understand the consequences** — certain combinations produce black or greyscale rendering.

UseINVBasicMaterial = 1    ; basic material system — working

UseUberMaterial     = 0    ; advanced materials — causes black faces

UseAccel            = 1    ; hardware acceleration

## Open Problems

Known issues with investigation leads. Each entry has enough context for a skilled developer to pick it up cold.

### 1. Materials Too Dark (highest priority)

**Symptom:** Material faces render noticeably darker than on Windows.

**Root cause:** The binary patch skips the portion of `OGSFactory.dll!fn@0x57968` that initialises the Protein material/lighting pipeline, because the COM call at RVA `0x57A40` returns `ppObject = NULL`.

**Investigation path:**
1. Use `OGSFactory.dll.original` (pre-patch) for analysis — it crashes but reveals the real call sequence
2. Set a `winedbg` breakpoint at RVA `0x57A40` (the `IEnumWbemClassObject::Next()` call)
3. Inspect `rax`/`rcx`/`rdx` after the call to identify the IID and vtable slot
4. Search Wine source for that IID — implement it if missing, or fix the return value if stubbed incorrectly
5. If the interface is a sub-query on the `Win32_TimeZone` instance, the fix belongs in `wbemprox`

**Fixing this will likely also fix:** Realistic Visual Style ("Material Library not available")

---

### 2. iLogic (COM Interop E_FAIL)

**Symptom:** iLogic addin fails with `E_FAIL 0x80004005` on `DesignProjectManager.get_ActiveDesignProject`.

**Investigation path:**
1. Re-enable the addin (move `autodesk.ilogic.inventor.addin` from `Bin/Addins/disabled/` back to `Bin/Addins/`)
2. Run with `WINEDEBUG=+ole,+rpc,err+all` and capture the COM trace
3. The failure is on a .NET → COM boundary via `ClrAddinLoader`
4. Check whether Wine's `ole32`/`oleaut32` correctly implements the specific `IDispatch` interface used by iLogic
5. May be a .NET 8 / wine-mono interop issue at the `IDispatch` marshalling layer

---

### 3. GPU Ray Tracing

**Symptom:** GPU ray tracing option is greyed out in Inventor's render settings.

**Root cause:** Requires D3D12 + DXR (DirectX Raytracing). Wine does not ship VKD3D-Proton by default.

**Fix path:** Install VKD3D-Proton, add `d3d12 = native` to DLL overrides, and test whether OGS detects the D3D12 device and enables the GPU RT path.

**Risk:** VKD3D-Proton and DXVK coexistence for D3D11/D3D12 needs testing.

---

### 4. Identity Manager Intermittent Deadlock

**Symptom:** Occasionally Identity Manager starts but never reaches "SSO Server is ready". Hangs in Boost.Interprocess lock acquisition.

**Current mitigation:** The launch script wipes the IPC directory before each start. This prevents the issue most of the time.

**Remaining edge case:** If the system is hard-killed while Identity Manager is running, stale `IDSDKQuit-v2-*` files from a different session path may survive and block the next start.

**Fix path:** Wipe all subdirectories under `.../IDSDK/<USERNAME_HEX>/interprocess/` before launch, not just the single session directory.

## Never Do These Things

These actions permanently break the Wine prefix or silently corrupt Inventor's state. There is no recovery path short of a full `rebuild-prefix.sh` run.

| Action | Consequence |
|--------|-------------|
| `winetricks dotnet48` | Removes wine-mono; all .NET loading breaks permanently |
| `mscoree = native` DLL override | Prevents PE loading entirely |
| Copy Windows .NET assemblies into wine-mono GAC | Triggers mono fatal assertion on every startup |
| Kill `wineserver` in OAuth callback | Destroys the running Inventor session |
| Place Proton `bcp47langs.dll` in system32 | NULL crash in all Autodesk apps |
| `UseUberMaterial=1` or `GammaCorrect=1` | Black / inverted face rendering |
| Update Wine without rebuilding wbemprox | Loses `Win32_TimeZone`; breaks CPU ray tracing |
| Leave IDSDK IPC directory dirty across restarts | Identity Manager deadlock on next launch |
