# Autodesk Inventor 2026 on Ubuntu 22.04 via Wine

This repository is an **Ubuntu 22.04 (Jammy) port** of the Inventor-on-Linux workflow originally demonstrated on Arch/CachyOS. It targets **Autodesk Inventor 2026 Professional + vanilla Wine 11.4 + DXVK 2.7.1**.

> **Important:** this project does not replace Autodesk's installer or licensing. You need a working Windows Inventor 2026 installation as the source, a valid Autodesk subscription, and a usable graphical Linux session for the final Wine launch.

> **Current Ubuntu-port status:** the workflow has been exercised through Windows staging, Wine-prefix reconstruction, Autodesk Identity/Licensing startup, WebView2 installation, and Inventor startup on Ubuntu 22.04. Compatibility remains build-sensitive: Wine is pinned to 11.4, DXVK to 2.7.1, and the OGS binary workaround is only applied to explicitly recognised DLL builds.

---

## What this repository does

The scripts build a Wine prefix by copying a **working Windows Inventor 2026 installation** and the Autodesk components it depends on.

The Ubuntu port additionally:

- installs Ubuntu 22.04 dependencies with `apt` instead of `pacman`;
- installs and pins **WineHQ development 11.4**;
- installs upstream **DXVK 2.7.1**;
- downloads the Microsoft **Edge WebView2 Evergreen x64** installer;
- installs WebView2 **after the Wine prefix exists and a real graphical Linux display is available**;
- verifies WebView2 using Microsoft's runtime registration rather than merely checking that the installer EXE exists;
- auto-detects Autodesk Identity Manager, Licensing, and Shared Components versions from the mounted Windows source;
- recreates Wine-side `Current` Autodesk component directories rather than copying broken NTFS junctions;
- launches Autodesk Licensing from the Wine-side `AdskLicensing\Current` directory;
- supports configurable Windows mount paths, data-drive mappings, GPU UUID selection, and server display variables;
- supports headless servers through a real X11/remote-desktop session;
- imports the Autodesk registry export generated by `export-registry.sh`;
- applies the Wine 11.4 `wbemprox` / `Win32_TimeZone` compatibility patch;
- refuses to apply the fixed-offset `OGSFactory.dll` patch to an unrecognised binary.

# Tested target

## Linux host

- **Ubuntu 22.04.x LTS (Jammy)**
- **x86_64**
- **Linux kernel 6.x or newer**
- Vulkan-capable GPU
- working 64-bit and required 32-bit Vulkan/NVIDIA userspace support
- a real graphical X11/Wayland session for Inventor itself

A server without a physical monitor is usable, but Inventor is still a GUI Windows application. A plain SSH shell with no graphical session is not enough.

For a Linux-only/headless server, a dedicated NVIDIA-backed Xorg display exposed through VNC is a suitable arrangement.

## Pinned compatibility stack

| Component | Required/tested version |
|---|---:|
| Wine | **11.4** WineHQ devel |
| DXVK | **2.7.1** |
| Inventor | **2026 Professional** |
| Windows compatibility mode | Windows 10 |
| Autodesk Identity Manager | auto-detected |
| Autodesk Licensing | auto-detected |
| Autodesk Shared Components | auto-detected |
| Microsoft Edge WebView2 | Evergreen x64 runtime |

Do not casually upgrade Wine or DXVK while debugging. The `wbemprox` patch is tied to Wine 11.4, while the OGS binary workaround is tied to specific Inventor DLL layouts.

# Windows source requirement

You need access to a Windows installation where Inventor 2026 is already installed.

By default:

```text
/mnt/windows
```

Required source locations include:

```text
Windows/System32
Program Files/Autodesk/Inventor 2026
Program Files/Autodesk/AdskIdentityManager/<version>
Program Files/Common Files/Autodesk Shared
Program Files (x86)/Common Files/Autodesk Shared/AdskLicensing/<version>
ProgramData/Autodesk
Users/<windows-user>/NTUSER.DAT
```

The source can be:

- a physical Windows partition;
- a read-only copy of a Windows filesystem; or
- the powered-off Windows staging VM described in `docs/windows-vm.md`.

## Linux-only server: staging VM

The repository includes a Windows 11 staging-VM workflow using:

- KVM/QEMU
- libvirt
- OVMF UEFI
- TPM 2.0
- VNC console

The intended lifecycle is:

1. create the Windows VM;
2. install Windows 11 Pro;
3. install and activate Inventor 2026 normally;
4. shut Windows down completely;
5. mount the Windows C: drive read-only at `/mnt/windows`;
6. rebuild the Wine prefix from that source.

**Never start the VM while its filesystem is mounted by Linux.**

See:

```text
docs/windows-vm.md
```

# Quick start

Run all repository scripts as the **normal Linux account that will run Inventor**. Do not run the whole workflow as root.

```bash
# 1. Configure the repository
cp inventor.env.example inventor.env
nano inventor.env

# 2. Install Ubuntu dependencies, Wine 11.4, DXVK and cache the WebView2 installer
bash scripts/phase0-setup.sh

# 3. Prepare/mount the Windows source
# For a Linux-only server, follow docs/windows-vm.md

# 4. Initial checks
bash scripts/doctor.sh

# 5. Export Autodesk registry data
bash scripts/export-registry.sh

# 6. Build the Wine prefix
bash scripts/rebuild-prefix.sh

# 7. Build/install the Wine 11.4 Win32_TimeZone patch
bash scripts/install-wbemprox-patch.sh

# 8. Register Autodesk OAuth callback + desktop integration
bash scripts/setup-user-integration.sh

# 9. Configure/start the real graphical Linux session used by Inventor
# On a headless server this may be a dedicated Xorg/VNC display.

# 10. Install and verify Microsoft Edge WebView2 inside the Wine prefix
bash scripts/install-webview2.sh

# 11. Final checks
bash scripts/doctor.sh

# 12. Launch
bash scripts/launch-inventor.sh
```

The rebuild is intentionally destructive to `WINEPREFIX`.

For unattended rebuilding:

```bash
bash scripts/rebuild-prefix.sh --force
```

# 2. Ubuntu host setup

Run:

```bash
bash scripts/phase0-setup.sh
```

Phase 0:

- verifies Ubuntu 22.04;
- verifies x86_64;
- verifies kernel 6.x+;
- enables i386 packages;
- enables Ubuntu Universe;
- installs build/runtime dependencies;
- configures WineHQ's Jammy repository;
- installs exactly Wine 11.4;
- holds the Wine packages;
- installs DXVK 2.7.1 into the user cache;
- downloads the Microsoft WebView2 Evergreen x64 installer;
- checks Vulkan;
- installs matching NVIDIA 32-bit userspace libraries when available.

## Important WebView2 distinction

Phase 0 **downloads**:

```text
~/.cache/inventor-on-linux/MicrosoftEdgeWebView2RuntimeInstallerX64.exe
```

It does **not** mean WebView2 is installed in the Wine prefix.

WebView2 must be installed after:

1. `rebuild-prefix.sh` has created the Wine prefix; and
2. Wine has access to the real graphical session that Inventor will use.

That step is:

```bash
bash scripts/install-webview2.sh
```

Do not treat the presence of the installer EXE as proof that the runtime is usable.

# 4. DXVK 2.7.1 and multi-GPU systems

DXVK is cached at:

```text
~/.local/share/dxvk/dxvk-2.7.1
```

List GPUs:

```bash
bash scripts/list-gpus.sh
```

On multi-GPU servers, configure the desired Vulkan device UUID:

```bash
DXVK_FILTER_DEVICE_UUID="0123456789abcdef0123456789abcdef"
```

Dashes are accepted in configuration; the launcher normalises the value.

For identical GPUs, use the UUID rather than relying on device names.

# 5. Graphical session / headless server setup

`vulkaninfo --summary` can work without `DISPLAY`, but Inventor cannot.

The repository resolves the graphical environment in this order:

1. explicit `INVENTOR_*` settings from `inventor.env`;
2. `DISPLAY` / `XAUTHORITY` already present in the current shell;
3. a same-user GNOME session.

Check:

```bash
bash scripts/doctor.sh
```

## Local GNOME session

If the same Linux account owns GNOME, the launcher can often reuse its environment.

Useful inspection:

```bash
pgrep -u "$(id -u)" -x gnome-shell

tr '\0' '\n' \
  < /proc/$(pgrep -u "$(id -u)" -x gnome-shell | head -1)/environ \
  | grep -E '^(DISPLAY|XAUTHORITY|DBUS_SESSION_BUS_ADDRESS|XDG_RUNTIME_DIR)='
```

Then configure `inventor.env` if needed:

```bash
INVENTOR_DISPLAY=":0"
INVENTOR_XAUTHORITY="/path/reported/by/your/session"
INVENTOR_XDG_RUNTIME_DIR="/run/user/1000"
INVENTOR_DBUS_SESSION_BUS_ADDRESS="unix:path=/run/user/1000/bus"
```

Use values from your own machine.

Do not use:

```bash
xhost +
```

## Headless server

For a server without a monitor, use a real Xorg session rather than `xvfb-run`.

A practical architecture is:

```text
NVIDIA GPU
    |
headless Xorg :1
    |
Openbox / lightweight WM
    |
x11vnc
    |
SSH tunnel
    |
TigerVNC Viewer
```

Example Inventor environment:

```bash
INVENTOR_DISPLAY=":1"
INVENTOR_XAUTHORITY="$HOME/.Xauthority-inventor"
```

Verify:

```bash
DISPLAY=:1 \
XAUTHORITY="$HOME/.Xauthority-inventor" \
xdpyinfo >/dev/null && echo OK
```

And ensure GLX is using NVIDIA rather than software rendering:

```bash
DISPLAY=:1 \
XAUTHORITY="$HOME/.Xauthority-inventor" \
glxinfo -B
```

Do not launch Inventor if the renderer is `llvmpipe`.

# 6. Prepare/mount the Windows source

A typical source mount looks like:

```text
/mnt/windows/Windows
/mnt/windows/Program Files
/mnt/windows/Program Files (x86)
/mnt/windows/ProgramData
/mnt/windows/Users
```

For the staging VM, shut the VM down first.

Ubuntu 22.04 may require libguestfs' direct backend and explicit partition selection.

Example:

```bash
sudo env LIBGUESTFS_BACKEND=direct \
  virt-filesystems \
    -a /var/lib/libvirt/images/inventor-win11.qcow2 \
    --all --long -h
```

After identifying the Windows partition:

```bash
sudo env LIBGUESTFS_BACKEND=direct \
  guestmount \
    -a /var/lib/libvirt/images/inventor-win11.qcow2 \
    -m /dev/sda3 \
    --ro \
    -o allow_other \
    -o uid="$(id -u)" \
    -o gid="$(id -g)" \
    /mnt/windows
```

`/dev/sda3` is only an example from the documented VM. Confirm the partition on your own image.

Verify:

```bash
findmnt /mnt/windows
ls -la /mnt/windows
ls "/mnt/windows/Program Files/Autodesk/Inventor 2026"
```

# 8. Rebuild the Wine prefix

Run:

```bash
bash scripts/rebuild-prefix.sh
```

or:

```bash
bash scripts/rebuild-prefix.sh --force
```

The rebuild performs a source-tree preflight before deleting an existing prefix.

Major operations include:

1. stop Wine and create a clean Wine 11.4 win64 prefix;
2. wait for the prefix registry and `%AppData%` to become usable;
3. configure Windows 10 mode;
4. install DXVK 2.7.1;
5. copy Inventor;
6. copy Autodesk Shared Components;
7. copy MSVC/MFC runtimes;
8. copy RealDWG;
9. copy Autodesk Identity Manager;
10. recreate `AdskIdentityManager\Current` as a real Wine-side directory;
11. copy Autodesk Licensing;
12. recreate `AdskLicensing\Current` as a real Wine-side directory;
13. copy available Autodesk license/cache files;
14. import `registry/autodesk-full.reg`;
15. add required Autodesk registry values;
16. install the IDSDK SSO plugin into the Licensing Agent;
17. disable known Wine-broken/non-essential add-ins;
18. disable CER;
19. remove problematic `bcp47langs` stubs;
20. copy available .NET runtime, Design Data, Templates and Textures;
21. validate/apply or deliberately skip the build-specific OGS workaround;
22. configure the optional `D:` mapping.

## WebView2 is deliberately a post-rebuild step

Do not rely on a headless WebView2 installation during the prefix rebuild.

The supported flow is:

```bash
bash scripts/rebuild-prefix.sh
# configure/start the real graphical session
bash scripts/install-webview2.sh
```

This avoids the case where the Evergreen installer returns non-zero while no usable X display exists, leaving Autodesk Licensing to fail later with:

```text
Web browser runtime could not be initialized
```

# 9. Wine `wbemprox` / `Win32_TimeZone` patch

Run:

```bash
bash scripts/install-wbemprox-patch.sh
```

The script:

1. downloads Wine 11.4 source;
2. applies `patches/wbemprox-timezone.patch`;
3. configures a minimal build tree;
4. builds only `dlls/wbemprox`;
5. locates the active WineHQ `wbemprox.dll`;
6. preserves the packaged DLL as `wbemprox.dll.inventor-original`;
7. installs the patched DLL with `sudo`.

## Patch header requirement

The patch file must use repository-relative paths compatible with `patch -p1`:

```text
--- a/dlls/wbemprox/builtin.c
+++ b/dlls/wbemprox/builtin.c
```

If the patch instead contains absolute `/tmp/...` paths, `patch -p1` will stop with:

```text
can't find file to patch
```

That is a patch-header problem, not a Wine 11.4 source incompatibility.

A correct Wine 11.4 dry-run should report the four hunks applying successfully.

# 11. Install Microsoft Edge WebView2

This is a required first-time step.

Ensure the real graphical Inventor session is running, then execute:

```bash
bash scripts/install-webview2.sh
```

The script:

- verifies the Wine prefix exists;
- requires a usable graphical display;
- checks whether WebView2 is already registered;
- creates a writable Autodesk Licensing WebView2 user-data directory;
- stops stale Wine processes;
- launches the Evergreen x64 installer;
- waits for runtime registration;
- fails with a timestamped log if the runtime cannot be detected.

The installer may display a graphical window.

## Detection

The runtime is checked using Microsoft's WebView2 Runtime GUID:

```text
{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}
```

The supported registration locations checked by the scripts are:

```text
HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\
{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}
```

and:

```text
HKCU\Software\Microsoft\EdgeUpdate\Clients\
{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}
```

The `pv` value must contain a non-zero version.

Manual check:

```bash
source scripts/common.sh

GUID='{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}'

"$WINE_BIN" reg query \
  "HKLM\\SOFTWARE\\WOW6432Node\\Microsoft\\EdgeUpdate\\Clients\\$GUID" \
  /v pv 2>&1 || true

"$WINE_BIN" reg query \
  "HKCU\\Software\\Microsoft\\EdgeUpdate\\Clients\\$GUID" \
  /v pv 2>&1 || true
```

## Autodesk licensing WebView2 user-data directory

The workflow ensures this is writable:

```text
C:\users\<linux-user>\Autodesk\AdskLicensingAgent
```

Wine-side path:

```text
$WINEPREFIX/drive_c/users/$USER/Autodesk/AdskLicensingAgent
```

# 12. Final doctor check

Run:

```bash
bash scripts/doctor.sh
```

After the prefix is built, `doctor.sh` checks both:

```text
WebView2 installer cached
WebView2 Runtime installed
```

These are intentionally separate checks.

It also checks that the Wine-side Licensing Service exists under:

```text
AdskLicensing\Current\AdskLicensingService\AdskLicensingService.exe
```

Fix all `FAIL` entries before launching Inventor.

A warning about missing `DISPLAY` is expected only if the shell is not attached/configured for the graphical session. For a final launch, configure the graphical variables.

# 13. Launch Inventor

Run:

```bash
bash scripts/launch-inventor.sh
```

The launcher:

- verifies Wine 11.4;
- validates the DXVK GPU UUID;
- validates the graphical session;
- verifies that Inventor exists;
- verifies the Wine-side Autodesk Licensing `Current` executable;
- detects WebView2;
- invokes `install-webview2.sh` if WebView2 is missing;
- ensures the Autodesk Licensing WebView2 user-data directory is writable;
- clears stale Autodesk IDSDK IPC state;
- initializes Wine;
- starts Autodesk Identity Manager;
- waits for Identity Manager readiness;
- starts Autodesk Licensing from:

```text
C:\Program Files (x86)\Common Files\Autodesk Shared\
AdskLicensing\Current\AdskLicensingService\
AdskLicensingService.exe
```

- launches Inventor;
- writes logs under `logs/`;
- shuts down the Wine prefix when the launched Inventor session exits.

Using `Current` is intentional.

`ADSK_LICENSING_VERSION="auto"` is a **source discovery setting**. It must never become a literal Windows launch path such as:

```text
AdskLicensing\auto\...
```

The rebuild creates a real Wine-side `Current` directory specifically so runtime launching is independent of the Windows source mount.

# Troubleshooting

## `pacman: command not found`

You are using old/original Arch instructions.

Use:

```bash
bash scripts/phase0-setup.sh
```

---

## Wine 11.4 not detected

```bash
wine --version 2>/dev/null || true
/opt/wine-devel/bin/wine --version
```

Repository scripts prefer `/opt/wine-devel/bin/wine`.

---

## WineHQ no longer exposes Wine 11.4

Check:

```bash
apt-cache madison winehq-devel
```

Do not silently substitute another Wine version without retesting the `wbemprox` patch.

---

## `DISPLAY` is unset over SSH

This is normal for a plain SSH shell.

Check:

```bash
bash scripts/doctor.sh
```

Configure `INVENTOR_DISPLAY` and `INVENTOR_XAUTHORITY` when required.

For a headless server, use a real remote X session rather than `xvfb-run`.

---

## `vulkaninfo` works but Inventor has no GUI

Vulkan enumeration and graphical X access are separate.

Check:

```bash
xdpyinfo
glxinfo -B
```

under the same `DISPLAY` / `XAUTHORITY` used by Inventor.

---

## DXVK chooses the wrong GPU

```bash
bash scripts/list-gpus.sh
```

Set the desired Vulkan UUID in:

```text
DXVK_FILTER_DEVICE_UUID
```

---

## `AdskLicensing\auto\...` failed to open

The runtime launcher must use the Wine-side `Current` directory.

Check:

```bash
find \
  "$HOME/.wine-inventor2026/drive_c/Program Files (x86)/Common Files/Autodesk Shared/AdskLicensing" \
  -iname AdskLicensingService.exe \
  -print
```

Expected runtime path:

```text
...\AdskLicensing\Current\AdskLicensingService\AdskLicensingService.exe
```

If `launch-inventor.sh` is trying to execute `AdskLicensing\auto\...`, update the launcher.

---

## Licensing Error: `Web browser runtime could not be initialized`

This normally means Autodesk Licensing cannot initialise Microsoft Edge WebView2.

Do not merely rerun Phase 0: Phase 0 only downloads the installer.

From the real graphical Inventor session run:

```bash
bash scripts/install-webview2.sh
```

Then:

```bash
bash scripts/doctor.sh
```

You want:

```text
OK   WebView2 Runtime installed: <version>
```

Also verify the licensing WebView2 data directory is writable:

```bash
mkdir -p \
  "$WINEPREFIX/drive_c/users/$USER/Autodesk/AdskLicensingAgent"

chmod -R u+rwX \
  "$WINEPREFIX/drive_c/users/$USER/Autodesk"
```

---

## WebView2 installer returns non-zero

The installer exit status is not the only signal.

The installation script checks whether Microsoft's runtime registration appears afterward.

Inspect:

```text
logs/webview2-install-YYYYMMDD-HHMMSS.log
```

If a valid WebView2 version is registered, the runtime is treated as installed even if the installer returned an unusual status.

---

## `wbemprox patch does not apply cleanly`

First determine whether the failure is actually:

```text
can't find file to patch
```

If so, inspect the first two patch headers.

Correct:

```text
--- a/dlls/wbemprox/builtin.c
+++ b/dlls/wbemprox/builtin.c
```

Incorrect legacy form:

```text
--- /tmp/builtin.c.orig
+++ /tmp/wine-11.4/dlls/wbemprox/builtin.c
```

With the correct headers, Wine 11.4 should accept the intended hunks with `patch -p1`.

---

## OGS patch refuses to run

This is deliberate.

`OGSFactory.dll` compatibility must be determined from its exact binary layout.

For one observed newer Inventor 2026 build dated **2026-06-29**, SHA-256:

```text
72b4bbbf8193526b1738197c4f8ad6c0b3848cac1cbd5880eb227924b0c5c177
```

the old crash-site signature is absent and the old code-cave offsets are not valid executable locations. That build should be recognised and left unmodified rather than force-patched.

Do not change fixed offsets without analysing the exact DLL.

---

## CER `senddmp.exe` missing

The rebuild intentionally disables Autodesk CER by renaming/removing the crash-report executable from its normal path.

A message similar to:

```text
The set senddmp exe does not exist
```

is therefore not, by itself, proof of the primary Inventor startup failure.

---

## `upi.exe` warnings

Do not assume the UPI warning is fatal before resolving Identity, Licensing, and WebView2.

Confirm whether the source actually contains the requested file:

```bash
find \
  "/mnt/windows/Program Files/Autodesk/Inventor 2026" \
  -maxdepth 5 \
  \( -iname 'upi.exe' -o -iname 'upiconfig.xml' \) \
  -print
```

---

## Autodesk component versions differ

The source configuration supports:

```bash
ADSK_IDENTITY_VERSION="auto"
ADSK_LICENSING_VERSION="auto"
ADSK_COMPONENTS_VERSION="auto"
```

The rebuild selects real numeric source directories.

Do not copy Windows `Current` junctions directly when using libguestfs/guestmount. They may appear as `/sysroot/...` symlinks.

The rebuild instead copies the resolved version and creates usable Wine-side `Current` directories.

# Technical details

## Wine `wbemprox` / `Win32_TimeZone`

`patches/wbemprox-timezone.patch` adds a `Win32_TimeZone` implementation to Wine's:

```text
dlls/wbemprox/builtin.c
```

The patch adds:

- the WMI column definition;
- timezone record structure;
- a `fill_timezone()` implementation based on `GetTimeZoneInformation()`;
- the class registration in Wine's built-in WMI table.

The patch is built specifically against Wine 11.4.

---

## Autodesk Identity Services IPC

Autodesk Identity Manager uses Boost.Interprocess.

The launcher clears:

```text
$WINEPREFIX/drive_c/ProgramData/Autodesk/IDSDK/<USERNAME_HEX>/interprocess
```

before startup.

Stale lock/session files can otherwise prevent:

```text
SSO Server is ready
```

from being reached.

---

## OAuth callback

The `adskidmgr://` callback must launch an Identity Manager client instance.

Do not kill `wineserver` from the OAuth callback: that would destroy the running Inventor session.

---

## CER

Autodesk CER can terminate the application after a recoverable Wine fault.

The rebuild disables CER's `senddmp.exe` intentionally.

---

## .NET 8

The observed .NET 8 load chain includes:

```text
ClrAddinLoader.dll
hostfxr.dll
hostpolicy.dll
coreclr.dll
```

The launcher uses:

```bash
WINEDLLOVERRIDES="msquic="
```

by default to prevent the .NET networking path from loading MSQUIC under Wine.

---

## OGSFactory binary compatibility

The historical OGS workaround was a fixed-offset machine-code patch for a specific DLL layout.

Fixed-offset binary patches must never be applied to an unknown `OGSFactory.dll`.

The rebuild therefore:

1. checks the expected crash-site bytes;
2. detects an already-patched known DLL;
3. applies the old patch only to the tested old layout;
4. recognises explicitly-supported newer hashes that should remain unmodified;
5. fails on any other unknown build.

This safety rule is intentional.

# Never do these while debugging

| Action | Consequence |
|---|---|
| `winetricks dotnet48` | Can replace/remove Wine Mono state required by this workflow |
| `mscoree=native` override | Can break PE/.NET loading |
| Copy arbitrary Windows .NET assemblies into Wine Mono's GAC | Can trigger fatal Mono failures |
| Kill `wineserver` inside the OAuth callback | Destroys the active Inventor session |
| Force an unknown OGS fixed-offset binary patch | Can corrupt `OGSFactory.dll` |
| Upgrade Wine without rebuilding/retesting `wbemprox` | Removes or invalidates the Wine compatibility patch |
| Leave stale IDSDK IPC state | Can deadlock Identity Manager |
| Treat the cached WebView2 installer as proof that WebView2 is installed | Leads to Autodesk Licensing browser-runtime failures |
| Launch Autodesk Licensing from `AdskLicensing\auto\...` | `auto` is configuration, not a real runtime directory |

# Recommended validation after first successful launch

Once Inventor reaches the main UI:

1. confirm Autodesk licensing remains valid;
2. confirm the expected GPU is being used;
3. create a new Part;
4. create a 2D sketch;
5. draw a rectangle;
6. finish the sketch;
7. extrude it;
8. rotate/pan/zoom the model;
9. save an `.ipt`;
10. close and reopen it.

On a multi-GPU NVIDIA server:

```bash
nvidia-smi
```

and compare activity with the configured:

```text
DXVK_FILTER_DEVICE_UUID
```
